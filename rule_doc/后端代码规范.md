# 🔵 后端研发交付标准（完整版）

**核心原则**：高并发可用、数据强一致性、接口契约化、可观测性。

### 1. 接口契约与数据规范（协作红线）
*   **【强制】文档即代码**：严禁口头约定接口。必须使用 Swagger/OpenAPI 自动生成文档，且文档必须与代码逻辑 100% 同步。
*   **【强制】统一响应体**：所有 HTTP 响应（含异常）必须包裹在统一结构中：`{ code, message, data }`。
*   **【强制】数据类型规范**：
    *   **金额/高精度**：必须传 `String` 或 `Long`（单位：分），**严禁**使用 `Double/Float` 传输金额。
    *   **时间**：必须传 `Unix Timestamp`（毫秒）或 `ISO 8601`，**严禁**使用 `yyyy-MM-dd HH:mm:ss` 这种带时区歧义的格式。

### 2. 高并发与架构设计（并发红线）
*   **【强制】N+1 问题零容忍**：**严禁**在循环（Loop）中调用数据库查询或 RPC 接口。必须使用 `WHERE IN` 批量查询后在内存组装。
*   **【强制】事务范围最小化**：`@Transactional` 事务内**严禁**执行 RPC 操作（发邮件、调支付、文件上传）。事务只包含纯数据库操作，防止连接池耗尽。
*   **【强制】非核心异步化**：注册发送欢迎短信、记录操作日志、积分计算等非核心逻辑，**必须**使用 MQ 或异步线程池解耦，主接口响应时间不得受此影响。
*   **【强制】并发写锁机制**：库存扣减、秒杀、抢单等高并发写场景，**严禁**单纯依赖数据库行锁。必须使用 Redis 分布式锁（+Lua脚本）或 数据库乐观锁（CAS）。
*   **【强制】限流熔断**：核心接口（QPS预期>500）必须配置 Sentinel/Hystrix 限流规则，超负荷时快速失败（Fast Fail）。

### 3. 数据库与 SQL 性能（存储红线）
*   **【强制】慢 SQL 阈值**：OLTP 业务单条 SQL 执行耗时（P99）**严禁超过 200ms**。
*   **【强制】索引覆盖**：所有 `WHERE`, `ORDER BY`, `GROUP BY` 涉及的字段必须由索引覆盖。禁止全表扫描。
*   **【强制】SQL 注入防御**：**严禁**使用字符串拼接 SQL。所有参数必须通过预编译（PreparedStatement/#{}）处理。

### 4. 安全、日志与可观测性
*   **【强制】敏感数据脱敏**：密码、手机号、身份证号在数据库必须加密存储；在 Log 日志中必须掩码处理（如 `138****0000`），**严禁明文打印密码**。
*   **【强制】水平越权校验（IDOR）**：涉及资源操作（改、删、查），**必须**校验“资源归属人”。不能仅判断“是否登录”，必须判断“该订单是否属于当前用户”。
*   **【强制】全链路 TraceID**：所有请求入口生成 TraceID 并贯穿整个调用链（Logback/MDC），确保能通过一个 ID 查完所有微服务日志。
*   **【强制】魔法值清理**：代码逻辑中**严禁**出现未定义的数字/字符串常量（如 `if type == 1`），必须定义枚举或常量类。
