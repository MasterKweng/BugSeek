本项目所有服务（前端构建、后端微服务、中间件、数据库）必须在以下指定的基准环境中稳定、流畅运行。**此环境的性能上限即为项目交付的最低性能标准。**

若在此配置下出现卡顿、OOM（内存溢出）或启动超时，请优先检查代码质量与资源调度策略。

## 一、硬件环境要求

### 1. 计算资源 (Compute & Processor)
*   **处理器型号**：AMD Ryzen™ 7 7840HS (Zen4 架构)
*   **核心规格**：8 Cores / 16 Threads (全大核)
*   **基准频率**：3.8 GHz (Max Boost 5.1 GHz)
*   **算力评估**：此 CPU 单核性能远超一般云服务器（如阿里云 ECS c7/g7 系列）。
    *   *这意味着：如果你的代码在这里跑满 CPU 甚至卡死，上线到生产环境只会死得更快。*

### 2. 内存与存储资源 (Memory & Storage)
*   **内存环境**：共享物理内存（具体大小受宿主机物理限制，通常上限为 16GB/32GB）
    *   *约束*：这是一个**全栈共享内存环境**。FastAPI 进程、Celery Worker、Redis 缓存、数据库 Buffer Pool、向量模型加载需争抢此资源。请严格控制各个服务的内存上限，严禁无限制申请内存。
    *   *推荐配置*：至少 16GB 可用内存，推荐 32GB 以支持完整的向量模型加载和AI推理。
*   **磁盘 I/O**：PCIe 4.0 NVMe SSD
*   **文件系统约束**：**WSL 2 Virtual Disk (ext4)**
    *   *警告*：WSL 2 跨文件系统（访问 Windows C/D 盘）性能极差。所有项目代码、数据库文件、日志文件**必须**存放于 Linux 系统内部路径（如 `/home/user/project`），严禁挂载 Windows 目录运行高 IO 任务。

### 3. 操作系统与内核 (OS & Kernel)
*   **运行环境**：Windows Subsystem for Linux 2 (WSL 2)
*   **发行版**：**Ubuntu 24.04 LTS (Noble Numbat)**
*   **内核版本**：Linux 5.15.x / 6.x (Microsoft Standard Kernel)
*   **网络模式**：NAT / localhost 环回

## 二、服务组件与配置要求

### 1. PostgreSQL 数据库

**作用**：存储项目数据、用户信息、API定义、字段映射结果等核心业务数据。

**版本要求**：PostgreSQL 15.x 或更高版本

**配置要求**：
```ini
# 数据库连接
Host: localhost
Port: 5432
Database: bugseek
Username: bugseek
Password: bugseek

# 内存配置（根据可用内存调整）
shared_buffers = 256MB          # 建议：可用内存的 25%
effective_cache_size = 1GB      # 建议：可用内存的 50-75%
work_mem = 16MB                 # 建议：可用内存 / 最大连接数
maintenance_work_mem = 128MB

# 连接配置
max_connections = 100

# 性能优化
random_page_cost = 1.1          # SSD 优化
effective_io_concurrency = 200  # SSD 并发IO
```

**启动方式**：
```bash
# Ubuntu/WSL2
sudo systemctl start postgresql
sudo systemctl enable postgresql

# 验证状态
sudo systemctl status postgresql
```

**内存占用预估**：
- 基础进程：~50MB
- Buffer Pool：根据 `shared_buffers` 配置
- 每个连接：~2-10MB（取决于查询复杂度）

---

### 2. Redis 缓存

**作用**：Celery 任务队列 Broker、任务结果存储、用户会话缓存、限流计数器。

**版本要求**：Redis 7.x 或更高版本

**配置要求**：
```ini
# Redis 配置
bind 127.0.0.1
port 6380
protected-mode yes

# 内存配置
maxmemory 512MB                 # 建议：512MB - 1GB
maxmemory-policy allkeys-lru    # 内存满时淘汰最少使用的键

# 持久化配置（可选，根据需求启用）
save ""                         # 禁用 RDB 持久化（提高性能）
appendonly no                   # 禁用 AOF 持久化（提高性能）

# 数据库分离
# DB 0: Celery Broker
# DB 1: Celery Result Backend
# DB 2-15: 应用缓存
```

**启动方式**：
```bash
# 启动 Redis（默认端口 6380）
redis-server --port 6380

# 或使用配置文件
redis-server /path/to/redis.conf

# 验证状态
redis-cli -p 6380 ping
# 返回 PONG 表示正常

# 查看内存使用
redis-cli -p 6380 INFO memory
```

**内存占用预估**：
- 基础进程：~10-20MB
- 数据缓存：根据实际数据量
- 建议预留：512MB - 1GB

---

### 3. Celery 异步任务队列

**作用**：处理耗时的字段映射任务、AI推理任务，避免阻塞主服务。

**版本要求**：Celery 5.3.0+

**配置要求**：
```python
# Celery 配置（app/celery_config.py）
broker_url = 'redis://127.0.0.1:6380/0'
result_backend = 'redis://127.0.0.1:6380/1'

# Worker 配置
worker_pool = 'solo'              # Windows 必须使用 solo 池
worker_prefetch_multiplier = 1    # 每个worker只预取1个任务
worker_max_tasks_per_child = 100  # 每个worker最多执行100个任务后重启

# 超时配置
task_time_limit = 3600            # 任务最大执行时间1小时
task_soft_time_limit = 3300       # 软超时55分钟

# 任务结果配置
result_expires = 3600             # 结果保存1小时
result_compression = 'gzip'       # 结果压缩
```

**启动方式**：
```bash
# Windows (PowerShell)
cd backend
.\start_celery_worker.bat

# Linux/WSL2
cd backend
./start_celery_worker.sh

# 或直接运行
celery -A app.celery_config worker --loglevel=info --pool=solo

# 验证状态
celery -A app.celery_config inspect active
```

**内存占用预估**：
- 基础进程：~50-100MB
- 每个任务：根据任务复杂度（向量模型加载可能需要 500MB-1GB）
- 建议预留：每个 Worker 1-2GB

**注意事项**：
- **Windows 兼容性**：必须使用 `--pool=solo` 参数
- **向量模型加载**：字段映射任务需要加载向量模型（~500MB），确保内存充足
- **任务超时**：长时间运行的任务需注意超时配置

---

### 4. FastAPI 后端服务

**作用**：提供 RESTful API、处理HTTP请求、业务逻辑处理。

**版本要求**：Python 3.10+

**配置要求**：
```python
# Uvicorn 配置
workers = 1                      # Windows 只能使用单进程
worker_class = 'uvicorn.workers.UvicornWorker'
max_requests = 1000              # 每个worker处理1000个请求后重启
max_requests_jitter = 100        # 重启时间抖动

# 连接池配置
pool_size = 10                   # 数据库连接池大小
max_overflow = 20                # 最大溢出连接数
pool_timeout = 30                # 连接超时时间

# 日志配置
log_level = 'info'
access_log = True
```

**启动方式**：
```bash
# 开发模式
cd backend
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 生产模式
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1

# 使用启动脚本
.\start_server.bat       # Windows
./start_server.sh        # Linux/WSL2
```

**内存占用预估**：
- 基础进程：~100-200MB
- 每个请求：~1-10MB（取决于请求复杂度）
- 建议预留：500MB - 1GB

**模型要求**：

## 三、服务启动顺序与依赖关系

### 启动顺序

1. **PostgreSQL** （必须）
   - 命令：`sudo systemctl start postgresql`
   - 验证：`psql -U bugseek -d bugseek -c "SELECT 1"`

2. **Redis** （必须）
   - 命令：`redis-server --port 6380`
   - 验证：`redis-cli -p 6380 ping`

3. **Celery Worker** （必须，用于异步任务）
   - 命令：`celery -A app.celery_config worker --loglevel=info --pool=solo`
   - 验证：`celery -A app.celery_config inspect active`

4. **FastAPI 服务** （必须）
   - 命令：`python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000`
   - 验证：访问 `http://localhost:8000/docs`

### 依赖关系

```
FastAPI 服务
    ├─→ PostgreSQL (必需)
    └─→ Redis (必需，用于用户缓存、限流)
        └─→ Celery Worker (必需，用于异步任务)
            ├─→ PostgreSQL (必需)
            └─→ Redis (必需，作为 Broker)
```

## 四、资源分配建议（16GB 内存环境）

| 服务 | 预留内存 | 说明 |
|------|---------|------|
| **PostgreSQL** | 512MB - 1GB | 包含 Buffer Pool 和连接池 |
| **Redis** | 512MB | 缓存和任务队列 |
| **Celery Worker** | 1GB - 2GB | 包含向量模型加载 |
| **FastAPI 服务** | 500MB - 1GB | 基础服务和请求处理 |
| **操作系统** | 2GB - 3GB | WSL2 和系统进程 |
| **向量模型缓存** | 500MB | sentence-transformers 模型 |
| **总计** | **5GB - 7.5GB** | 剩余 8-11GB 可用 |

**注意**：如果可用内存不足 16GB，建议：
1. 减少 PostgreSQL 的 `shared_buffers` 配置
2. 减少 Redis 的 `maxmemory` 配置
3. 限制 Celery Worker 的并发数
4. 使用轻量级的向量模型

## 六、常见问题排查

### 1. Redis 连接失败

**症状**：`Error 10061 connecting to localhost:6380`

**解决**：
```bash
# 检查 Redis 是否运行
redis-cli -p 6380 ping

# 如果未运行，启动 Redis
redis-server --port 6380

# 检查端口是否被占用
netstat -an | grep 6380
```

### 2. Celery Worker 无法启动

**症状**：Worker 启动失败或任务不执行

**解决**：
```bash
# 检查 Celery 配置
python -c "from app.celery_config import celery_app; print(celery_app.conf.broker_url)"

# 检查任务是否注册
celery -A app.celery_config inspect registered

# Windows 环境确保使用 solo 池
celery -A app.celery_config worker --loglevel=info --pool=solo
```

### 3. 内存不足

**症状**：服务崩溃或系统响应迟钝

**解决**：
```bash
# 查看内存使用
free -h

# 清理 Redis 缓存
redis-cli -p 6380 FLUSHDB

# 清理 Celery 结果
redis-cli -p 6380 SELECT 1
redis-cli -p 6380 FLUSHDB

# 重启服务释放内存
sudo systemctl restart postgresql
```

### 4. 向量模型加载失败

**症状**：字段映射任务报错 "Model not found"

**解决**：
```bash
# 检查模型目录
ls -la backend/data/models/

# 手动下载模型（如果自动下载失败）
cd backend
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('all-MiniLM-L6-v2')"
```

## 七、给研发团队的执行要求

1. **资源自洽**：所有服务启动后，不得导致宿主机内存溢出或响应迟钝。
2. **兼容性**：后端脚本与构建流程必须适配 Ubuntu 24.04 环境（注意 OpenSSL 版本及 Glibc 兼容性）。
3. **服务隔离**：不同服务的配置文件、日志文件、数据文件应相互隔离，避免冲突。
4. **日志管理**：所有服务应配置日志轮转，避免日志文件无限增长占用磁盘空间。
5. **错误处理**：服务启动失败应提供清晰的错误信息，便于快速排查问题。
6. **性能优化**：定期监控各服务的资源使用情况，及时优化配置。
7. **备份策略**：定期备份 PostgreSQL 数据库，避免数据丢失。
8. **安全配置**：生产环境应修改默认密码，配置防火墙规则，限制访问权限。
