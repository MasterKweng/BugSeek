# BugSeek 全局设计参考

## 功能分类方案

  - 查看版本快照
- **多环境与变量管理**

  - 查看变量列表
  - 获取环境配置

#### 1. 需求洞察模块

  - 生成当前项目需求的思维导图
- **功能用例生成**
  - 生成当前项目的测试用例

#### 2. 代码级质量模块
- **单测自动生成**
  - 为当前项目生成单元测试
- **AI 代码审查**
  - 审查当前项目的代码
- **SQL 性能预警**
  - 扫描当前项目的 SQL

#### 3. 接口与集成模块
- **文档管理**
  - 查看文档列表
  - 查看文档详情
- **接口管理**
  - 查看接口列表
  - 查看接口详情
- **智能场景组装**
  - 生成当前项目的场景测试
- **智能 Mock 服务**
  - 启动当前项目的 Mock 服务

#### 4. UI 与端到端模块
- **自愈合 UI 自动化**

### 🔍 使用 ID 查询参数方案（灵活覆盖）

这些功能需要跨项目/版本查询，或者需要明确指定目标：

#### 0. 项目与空间管理中心
- **项目列表查询**
  - `GET /projects` - 获取所有项目（不需要 project_id）
- **项目切换**
  - `POST /context/switch` - 切换当前项目/版本（需要 project_id, version_id）
- **版本对比**
  - `GET /versions/{id}/compare/{target_id}` - 对比两个版本（需要两个 version_id）

#### 1. 需求洞察模块
- **跨项目需求对比**
  - `GET /requirements/compare?project_id={id1}&project_id={id2}` - 对比两个项目的需求
- **历史需求查询**
  - `GET /requirements?version_id={id}` - 查询特定版本的需求

#### 2. 代码级质量模块
- **跨项目代码审查**
  - `POST /code-review/compare?project_id={id1}&project_id={id2}` - 对比两个项目的代码
- **历史代码查询**
  - `GET /code?version_id={id}` - 查询特定版本的代码

#### 3. 接口与集成模块
- **跨项目接口对比**
  - `GET /endpoints/compare?project_id={id1}&project_id={id2}` - 对比两个项目的接口
- **历史接口查询**
  - `GET /endpoints?version_id={id}` - 查询特定版本的接口
- **导入文档**
  - `POST /documents/import?project_id={id}&version_id={id}` - 明确指定导入到哪个项目/版本

#### 4. UI 与端到端模块
- **跨项目 UI 对比**
  - `GET /ui/compare?project_id={id1}&project_id={id2}` - 对比两个项目的 UI
- **历史 UI 查询**
  - `GET /ui/screenshots?version_id={id}` - 查询特定版本的 UI 截图

#### 5. 流程编排与门禁模块
- **跨项目流水线对比**
  - `GET /pipelines/compare?project_id={id1}&project_id={id2}` - 对比两个项目的流水线
- **历史流水线查询**
  - `GET /pipelines?version_id={id}` - 查询特定版本的流水线

#### 6. 基础设施与数据支撑
- **跨项目数据对比**
  - `GET /data/compare?project_id={id1}&project_id={id2}` - 对比两个项目的数据
- **历史数据查询**
  - `GET /data?version_id={id}` - 查询特定版本的数据

## 🎯 混合使用方案（推荐）

对于某些功能，建议使用混合方案：

### 示例：接口管理

```python
@router.get("/endpoints")
async def get_endpoints(
    project_id: Optional[int] = None,  # 可选，覆盖 Session
    version_id: Optional[int] = None,  # 可选，覆盖 Session
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user)
):
    # 优先使用查询参数，否则使用 Session 上下文
    context = get_current_context(db, current_user)
    project_id = project_id or context.project_id
    version_id = version_id or context.version_id
    
    # 查询逻辑
    query = db.query(ApiEndpoint).filter(
        ApiEndpoint.project_id == project_id
    )
    if version_id:
        query = query.join(VersionEndpoint).filter(
            VersionEndpoint.version_id == version_id
        )
    return query.all()
```

**使用场景：**
- **默认情况**：前端不传参数，自动使用 Session 中的项目/版本
- **跨项目查询**：前端传 `project_id`，覆盖 Session 中的值
- **历史版本查询**：前端传 `version_id`，查询特定版本的数据

## 📊 总结统计

| 模块 | Session 方案 | ID 方案 | 混合方案 |
|------|-------------|---------|---------|
| 0. 项目与空间管理 | 3 | 3 | 0 |
| 1. 需求洞察 | 3 | 2 | 0 |
| 2. 代码级质量 | 3 | 2 | 0 |
| 3. 接口与集成 | 4 | 3 | 1 |
| 4. UI 与端到端 | 3 | 2 | 0 |
| 5. 流程编排 | 3 | 2 | 0 |
| 6. 基础设施 | 3 | 2 | 0 |
| **总计** | **22** | **16** | **1** |

**建议：**
- **22 个功能**使用 Session 上下文（默认行为，简化前端代码）
- **16 个功能**使用 ID 查询参数（跨项目/版本查询）
- **1 个功能**使用混合方案（灵活覆盖）

这样可以在保证灵活性的同时，最大程度地减少代码重复。
