# 鉴权配置详细设计方案

## 一、核心设计理念

### 1.1 架构思想
**"解耦注入逻辑与获取逻辑"** - 将鉴权配置拆分为两个独立但关联的层面：

- **主弹窗（Consumer 层）**：定义"如何使用凭证"
  - 鉴权类型选择
  - 注入位置（Header/Query/Cookie）
  - 注入模板（支持自定义前缀）

- **子抽屉（Producer 层）**：定义"如何获取凭证"
  - 引用 API 资产库中的登录接口
  - 参数映射（环境变量 → 登录接口参数）
  - 提取规则（从响应中提取 Token/CSRF 等）

### 1.2 核心优势
1. **模板化注入**：支持自定义格式（如 `Token {{ACCESS_TOKEN}}`），解决非标准鉴权问题
2. **资产库复用**：登录接口从 API 资产库引用，避免重复配置
3. **多值提取**：支持同时提取 Token、CSRF Token 等多个值
4. **隔离执行**：登录接口使用独立鉴权，防止递归调用

## 二、数据模型设计

### 2.1 数据库表结构

```sql
CREATE TABLE auth_configs (
    id INTEGER PRIMARY KEY,
    project_id INTEGER NOT NULL UNIQUE,
    enabled BOOLEAN NOT NULL DEFAULT FALSE,
    
    -- 主弹窗配置（Consumer 层）
    auth_type VARCHAR(50) NOT NULL,  -- basic/bearer/api_key/session/custom/none
    injection_target VARCHAR(20) NOT NULL,  -- header/query/cookie
    injection_key VARCHAR(100),  -- 如 Authorization、X-API-Key
    injection_template TEXT,  -- 如 "Bearer {{ACCESS_TOKEN}}"、"Token {{ACCESS_TOKEN}}"
    
    -- 来源模式
    source_mode VARCHAR(20) NOT NULL,  -- static/dynamic
    
    -- 静态模式数据
    static_value TEXT,  -- 直接填写的凭证值
    
    -- 动态模式数据（Producer 层）
    login_api_id INTEGER,  -- 引用 API 资产库中的接口 ID
    
    -- 创建时间、更新时间等标准字段
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE auth_input_mappings (
    id INTEGER PRIMARY KEY,
    auth_config_id INTEGER NOT NULL,
    param_location VARCHAR(20) NOT NULL,  -- body/query/header
    param_key VARCHAR(100) NOT NULL,  -- 参数名
    param_value TEXT NOT NULL,  -- 支持环境变量 {{env_var}}
    
    FOREIGN KEY (auth_config_id) REFERENCES auth_configs(id) ON DELETE CASCADE
);

CREATE TABLE auth_extract_rules (
    id INTEGER PRIMARY KEY,
    auth_config_id INTEGER NOT NULL,
    rule_name VARCHAR(50) NOT NULL,  -- 变量名，如 ACCESS_TOKEN、CSRF_TOKEN
    extract_source VARCHAR(20) NOT NULL,  -- body/header/cookie
    extract_expression TEXT NOT NULL,  -- JSONPath 或 Header 名或 Cookie 名
    
    FOREIGN KEY (auth_config_id) REFERENCES auth_configs(id) ON DELETE CASCADE
);
```

## 五、执行引擎（Runner）逻辑

### 5.1 鉴权中间件流程

```
┌─────────────────────────────────────────┐
│  1. 加载环境鉴权配置                     │
│     → 读取 auth_config                   │
│     → 解析 auth_type、injection          │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│  2. 检查凭证状态                         │
│     → source_mode == 'static'           │
│       → 直接使用 static_value            │
│     → source_mode == 'dynamic'          │
│       → 检查缓存是否有效                  │
│       → 无效则执行登录流程                │
└──────────────┬──────────────────────────┘
               │
               ▼ (需要登录)
┌─────────────────────────────────────────┐
│  3. 执行登录流程（隔离执行）              │
│     ├─ 加载 login_api_id 对应的 API      │
│     ├─ 应用 input_mappings（替换变量）   │
│     ├─ 【关键】标记为 No-Auth            │
│     ├─ 发送登录请求                       │
│     └─ 接收响应                           │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│  4. 提取凭证（Universal Extractor）      │
│     For each extract_rule:               │
│       ├─ source == 'body'                │
│       │   → JSONPath 提取                │
│       ├─ source == 'header'              │
│       │   → 从 Response Header 提取      │
│       └─ source == 'cookie'              │
│           → 从 Set-Cookie 提取            │
│     → 存入变量池 { ACCESS_TOKEN: ... }   │
│     → 更新缓存                           │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│  5. 最终组装请求                         │
│     ├─ 读取 injection.value_template      │
│     ├─ 替换变量 {{ACCESS_TOKEN}} → "..." │
│     ├─ 特殊处理 auth_type                 │
│     │   → Basic: Base64 编码            │
│     │   → 其他: 直接注入                 │
│     └─ 构造最终请求                       │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│  6. 发送业务请求                         │
└─────────────────────────────────────────┘
```

### 5.2 关键代码逻辑

```python
class AuthMiddleware:
    def __init__(self, auth_config: dict, env_variables: dict):
        self.auth_config = auth_config
        self.env_vars = env_variables
        self.token_cache = {}
    
    async def apply_auth(self, request: dict) -> dict:
        """应用鉴权到请求"""
        if not self.auth_config.get('enabled'):
            return request
        
        # 1. 获取凭证
        auth_value = await self._get_auth_value()
        
        # 2. 注入到请求
        return self._inject_to_request(request, auth_value)
    
    async def _get_auth_value(self) -> str:
        """获取凭证值（支持静态和动态）"""
        source_mode = self.auth_config.get('source_mode')
        
        if source_mode == 'static':
            return self.auth_config.get('static_value', '')
        
        # 动态模式
        cached = self._get_cached_token()
        if cached and not self._is_expired(cached):
            return cached['value']
        
        # 执行登录
        return await self._perform_login()
    
    async def _perform_login(self) -> str:
        """执行登录流程（隔离执行）"""
        login_api_id = self.auth_config.get('login_api_id')
        input_mappings = self.auth_config.get('input_mappings', [])
        extract_rules = self.auth_config.get('extract_rules', [])
        
        # 1. 构建登录请求
        login_request = self._build_login_request(input_mappings)
        
        # 2. 【关键】标记为隔离执行，避免递归
        login_request['_internal_no_auth'] = True
        
        # 3. 执行登录
        response = await self._execute_login_api(login_request)
        
        # 4. 提取凭证
        extracted = self._extract_from_response(response, extract_rules)
        
        # 5. 缓存凭证
        self._cache_token(extracted)
        
        return extracted.get('ACCESS_TOKEN', '')
    
    def _extract_from_response(self, response: dict, rules: list) -> dict:
        """通用提取器"""
        extracted = {}
        
        for rule in rules:
            name = rule['name']
            source = rule['source']
            expression = rule['expression']
            
            if source == 'body':
                # JSONPath 提取
                value = self._extract_from_body(response['body'], expression)
            elif source == 'header':
                # Header 提取
                value = response['headers'].get(expression, '')
            elif source == 'cookie':
                # Cookie 提取
                value = self._extract_from_cookie(response['headers'].get('Set-Cookie', ''), expression)
            
            extracted[name] = value
        
        return extracted
    
    def _inject_to_request(self, request: dict, auth_value: str) -> dict:
        """注入凭证到请求"""
        injection = self.auth_config.get('injection', {})
        auth_type = self.auth_config.get('auth_type')
        
        target = injection.get('target', 'header')
        key = injection.get('key')
        template = injection.get('value_template', '{{AUTH_VALUE}}')
        
        # 特殊处理 Basic Auth
        if auth_type == 'basic':
            username = self._resolve_value(template, auth_value)
            password = self._resolve_value('{{AUTH_VALUE}}', auth_value)
            encoded = base64.b64encode(f"{username}:{password}".encode()).decode()
            request['headers'][key] = f"Basic {encoded}"
        else:
            # 通用模板替换
            final_value = self._resolve_value(template, auth_value)
            
            if target == 'header':
                request['headers'][key] = final_value
            elif target == 'query':
                request['params'][key] = final_value
            elif target == 'cookie':
                request['cookies'][key] = final_value
        
        return request
    
    def _resolve_value(self, template: str, auth_value: str) -> str:
        """解析模板变量"""
        return template.replace('{{AUTH_VALUE}}', auth_value)
```

## 七、技术实现要点

### 7.1 防止递归调用
在执行登录接口时，必须在请求头添加内部标记：
```python
request['_internal_no_auth'] = True
```

Runner 中间件检查此标记：
```python
if request.get('_internal_no_auth'):
    # 跳过鉴权中间件
    return request
```

### 7.2 Session 自动追踪
对于 Session 模式，建议使用 `httpx` 的 `AsyncClient`：
```python
async with httpx.AsyncClient() as client:
    # 自动处理 Set-Cookie
    response = await client.post(...)
    # 后续请求自动携带 Cookie
```

### 7.3 变量命名规范
- 强制使用统一变量名：`{{AUTH_VALUE}}`、`{{ACCESS_TOKEN}}`
- 抽屉中的 `rule_name` 必须与主弹窗模板中的变量名一致
- 避免使用特殊字符，建议使用 `ACCESS_TOKEN`、`CSRF_TOKEN`、`API_KEY` 等

### 7.4 缓存策略
```python
{
  "value": "9944b09199c62bcf...",
  "expire_time": "2026-02-05T18:00:00Z",
  "login_time": "2026-02-05T17:00:00Z"
}
```

- 默认缓存时间：1 小时
- 可在配置中自定义 `cache_ttl`
- 支持手动刷新和过期自动刷新

## 八、开发注意事项

### 8.1 前端开发
1. **类型切换**：切换鉴权类型时，动态显示/隐藏对应配置项
2. **变量提示**：在输入框中提示可用的环境变量（如 `{{env_user}}`）
3. **实时校验**：JSONPath 表达式实时校验，提供语法提示
4. **测试功能**：抽屉中提供"立即运行"按钮，展示提取结果

### 8.2 后端开发
1. **统一响应体**：所有接口返回 `{ code, message, data }`
2. **TraceID 日志**：全链路日志追踪，便于调试
3. **错误处理**：登录失败时返回详细错误信息
4. **并发控制**：防止多个请求同时触发登录

### 8.3 数据库设计
1. **索引优化**：`project_id`、`auth_config_id` 建立索引
2. **外键约束**：删除配置时级联删除映射和提取规则
3. **数据迁移**：支持从旧版本配置迁移到新架构

## 九、扩展性设计

### 9.1 支持新的鉴权类型
只需在主弹窗添加新的 `auth_type` 选项：
```python
class AuthType:
    NONE = "none"
    BASIC = "basic"
    BEARER = "bearer"
    API_KEY = "api_key"
    SESSION = "session"
    CUSTOM = "custom"
    # 未来可扩展
    OAUTH2 = "oauth2"
    AWS_SIG = "aws_sig"
```

### 9.2 支持多步骤认证
通过 `extract_rules` 数组支持提取多个值：
```json
{
  "extract_rules": [
    { "name": "ACCESS_TOKEN", "source": "body", "expression": "$.token" },
    { "name": "REFRESH_TOKEN", "source": "body", "expression": "$.refresh_token" },
    { "name": "EXPIRES_IN", "source": "body", "expression": "$.expires_in" }
  ]
}
```

### 9.3 支持条件提取
未来可扩展 `extract_rules` 支持条件判断：
```json
{
  "extract_rules": [
    {
      "name": "ACCESS_TOKEN",
      "source": "body",
      "expression": "$.token",
      "condition": "$.status == 'success'"
    }
  ]
}
```

## 十、总结

这个设计方案通过以下核心机制实现了高度的灵活性和可扩展性：

1. **模板化注入**：通过 `value_template` 支持任意格式
2. **变量连接**：通过 `{{VAR_NAME}}` 连接 Producer 和 Consumer
3. **资产库复用**：登录接口从 API 资产库引用
4. **通用提取器**：支持从 Body、Header、Cookie 提取
5. **隔离执行**：防止递归调用，保证稳定性

这是一个工业级的、可扩展的鉴权配置方案，能够兼容当前和未来可能的几乎所有鉴权方式。
