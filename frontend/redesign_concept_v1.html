Redesign Direction

把 BugSeek 从“功能列表”重构成“任务工作台”。

当前前端的问题不是组件不够，而是信息架构偏散、顶栏菜单过重、项目与版本上下文不够稳定， 导致用户在 API 资产、场景编排、执行分析之间频繁跳转。建议把导航改成“一级领域 + 二级工作流”， 让项目/版本上下文固定在壳层，页面统一走工作台模板，而不是每页各自组织。

导航结构 三级改两层
视觉方向 从通用暗色改为实验室工作台
技术实现 仍基于 React + AntD + Router
落地方式 先壳层后页面
Refactor Principles
1
以项目/版本为固定上下文

顶部只保留上下文切换、全局搜索、用户入口，不再承担完整导航。

2
按工作流重组菜单

把“API Hub / 版本中心 / 场景工作室 / UI 自动化”串成真实操作路径。

3
统一页面骨架

每页默认包含标题区、指标区、主内容区、侧边上下文区，减少视觉漂移。

平台与治理

把项目、版本、知识图谱、环境、鉴权统一收口，作为平台能力层，而不是散在主导航里。
版本基线卡片

知识图谱关系视图
接口、表结构、场景节点之间的联动。
环境 / 鉴权配置
风险提示、过期状态、变更记录。
导航建议 一级导航用图标纵向导航，二级导航承载当前领域的工作流。
主题建议 改为浅底实验室风格，夜间模式作为可切换选项，而不是默认。
交互建议 增加全局命令搜索、固定上下文栏、统一右侧信息面板。
实施建议 先重构壳层和路由元数据，再逐页迁移，避免一次性推翻页面逻辑。
