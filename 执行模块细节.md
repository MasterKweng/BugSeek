## 1.4 历史数据回填 SQL

### 目标

尽可能给老数据补基础字段。

注意：

* `version_id` 基本无法完全准确回填，只能留空或结合你当前上下文策略另写脚本
* `case_id / definition_id` 可以部分回填

```sql id="zvy9d6"
BEGIN;

-- 回填 execution.result_status
UPDATE test_executions
SET result_status = CASE
    WHEN COALESCE(failed, 0) > 0 AND COALESCE(passed, 0) > 0 THEN 'partial_failed'
    WHEN COALESCE(failed, 0) > 0 AND COALESCE(passed, 0) = 0 THEN 'failed'
    WHEN COALESCE(passed, 0) > 0 AND COALESCE(failed, 0) = 0 THEN 'passed'
    WHEN COALESCE(skipped, 0) = COALESCE(total, 0) AND COALESCE(total, 0) > 0 THEN 'skipped'
    ELSE 'unknown'
END
WHERE result_status IS NULL;

-- 回填 execution.title（仅 single 类型）
UPDATE test_executions e
SET title = CONCAT('单用例执行：', c.name),
    summary_json = jsonb_build_object(
        'case_id', c.id,
        'case_name', c.name,
        'definition_id', d.id,
        'method', d.method,
        'path', d.path
    )
FROM api_cases c
JOIN api_definitions d ON d.id = c.definition_id
WHERE e.execution_type = 'single'
  AND e.target_id = c.id
  AND e.title IS NULL;

-- 回填 result.case_id / result.definition_id / result.target_name
UPDATE test_execution_results r
SET case_id = e.target_id,
    definition_id = COALESCE(r.target_id, c.definition_id),
    target_name = COALESCE(c.name, d.summary, d.path)
FROM test_executions e
LEFT JOIN api_cases c ON c.id = e.target_id
LEFT JOIN api_definitions d ON d.id = COALESCE(r.target_id, c.definition_id)
WHERE r.execution_id = e.id
  AND e.execution_type = 'single'
  AND (r.case_id IS NULL OR r.definition_id IS NULL OR r.target_name IS NULL);

COMMIT;
```

# 六、最终建议

如果你准备正式开做，这一版已经足够作为开发基线。

最核心的落地点就三件事：

1. **先把执行表补成“执行中心主表”**
2. **再把结果表补成“结果展示主表”**
3. **最后新增 execution/report 两套读侧 API**

这样你后面接：

* 场景执行
* 套件执行
* CI 执行
* 定时执行
* AI 失败分析

都不需要推翻。
