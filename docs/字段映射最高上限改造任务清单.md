# 字段映射最高上限改造任务清单

## 目标

在现有 `engine_v2` 骨架上，逐步补齐强证据层、裁决层、高风险守门层和运行时验证层，把字段映射能力从“生产可用”升级为“高可靠上限版”。

## 执行原则

1. 保留当前 `FieldMappingAppService -> recall -> rules -> rank -> AI -> suggestion` 主链。
2. 优先做对后续阶段有复用价值的基础设施，不推倒重做。
3. 每一批任务都要求“可接入、可观察、可回退”，避免一次性堆过大改动。
4. AI 继续只做受控补全，不绕过规则和强证据。

## 改动顺序

### Task 1：补任务骨架与统一上下文

范围：

1. 扩展 `contracts.py`，补充 `risk_level`、`domain_anchor`、`allowed_tables`、`api_summary`、`module_tag`、`confidence_bucket`、`review_policy` 等统一字段。
2. 调整 `services.py` 的 recall item 结构，让后续 lineage / calibrator / relation classifier 可以直接消费。
3. 调整 `job_runner.py` 的 artifact payload，让 Stage 2/3/4/5 可以携带新增上下文。

验收：

1. `field_specs` 和 `recall_candidates` 中包含统一上下文字段。
2. 不影响现有 `engine_v2` 主流程运行。

### Task 2：落地 Phase 1 基础设施

范围：

1. 新增 `data_impact/sql_lineage_parser.py`。
2. 新增 `data_impact/orm_lineage_parser.py`。
3. 新增 `data_impact/code_lineage_parser.py`。
4. 新增 `data_impact/lineage_repository.py`。
5. 新增 `data_impact/lineage_service.py`。
6. 新增 `field_mapping_engine/recall/sql_lineage_recaller.py`。
7. 新增 `field_mapping_engine/recall/code_lineage_recaller.py`。

验收：

1. 主链可返回 `sql_lineage` / `code_lineage` 候选。
2. lineage 候选即使是首版，也有稳定统一的数据结构和 feature 命名。

### Task 3：接入主编排并扩 recall merge

范围：

1. 在 `FieldMappingAppService.__init__()` 注入新的 lineage recaller。
2. 在 `build_recall_artifacts()` 中接入 `sql_lineage` / `code_lineage`。
3. 扩展 `_merge_candidate_evidence()`，保留来源、features 和原始 payload。

验收：

1. recall candidates 中出现 `f_sql_*` / `f_code_*` 特征。
2. 不破坏现有 lexical / vector / runtime 召回。

### Task 4：升级裁决层

范围：

1. 新增 `ranking/confidence_calibrator.py`。
2. 新增 `evidence/relation_classifier.py`。
3. 新增 `evidence/feature_builder.py`。
4. 重写 `ranking/ranker.py` 为三段式：短路、强特征打分、margin 调整。
5. 从 `services.py` 中剥离 `_calibrate_confidence()` 和 `_infer_relation_type()`。

验收：

1. `score` 与 `confidence` 分离。
2. `relation_type` 细化。
3. 输出包含 `review_policy` 与 `confidence_bucket`。

### Task 5：升级规则层

范围：

1. 新增 `evidence/domain_anchor.py`。
2. 新增 `evidence/risk_policy.py`。
3. 新增 `evidence/enum_dictionary.py`。
4. 扩展 `deterministic_rules.py`，加入高风险、位置、anchor、派生字段和枚举规则。

验收：

1. 高风险字段不能仅依赖弱证据自动通过。
2. `Count/Total/Display*` 等派生字段不会轻易被判成 `direct`。

### Task 6：增强 history / lexical / vector

范围：

1. 扩展 `history_recaller.py`，支持跨版本、path pattern、domain prior 和反馈权重。
2. 扩展 `lexical_recaller.py`，支持 acronym、token role、sibling context、enum pair。
3. 扩展 `vector_recaller.py`，支持 richer context 和 allowed tables。
4. 新增 `evidence/context_builder.py` 与 `evidence/feedback_weighting.py`。

验收：

1. top3 覆盖率提升。
2. 高风险字段不会被向量弱语义带偏。

### Task 7：增强 runtime verification

范围：

1. 新增 `runtime/response_field_verifier.py`。
2. 新增 `runtime/sql_projection_verifier.py`。
3. 新增 `runtime/execution_value_matcher.py`。
4. 新增 `runtime/runtime_verification_service.py`。
5. 扩展 `runtime_recaller.py` 和 `impact_repository.py`。

验收：

1. runtime evidence 不再只停留在 table prior。
2. 可产出 `runtime_column_verified`、`response_value_match`、`sql_projection_verified` 等证据。

## 当前执行批次

当前从 `Task 1` 开始，并在完成 `Task 1` 后立即进入 `Task 2` 的骨架落地。
