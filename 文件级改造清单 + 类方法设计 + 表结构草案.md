可以。下面这版我直接按你**当前 V2.0 代码结构**来写，目标是让你拿去就能拆任务。

先定基线：

当前主链是 `FieldMappingAppService` 编排各召回器、规则、排序器、AI，再产出 `DecisionArtifact` 。
当前排序器还是 `Minimal ranker for Phase 2` 的线性加权模型 。
当前规则层已经有 runtime/history/feedback/weak evidence 的拒绝与短路能力 。
当前契约层已经有 `ApiFieldSpec / CandidateEvidence / DecisionArtifact / StageArtifactEnvelope`，说明继续扩展最合适，没必要推翻 。
当前 runtime 还是“表 prior + `SchemaMapper.map_field()`”模式，不是 SQL/代码血缘 。
当前 lexical / vector / history 也都还是 Phase 2 级别的实现   。

---

# 总体改造原则

这 5 个 Phase 不是 5 套平行方案，而是一条连续升级路径：

1. Phase 1 补**强证据层**
2. Phase 2 补**裁决层**
3. Phase 3 补**高风险守门层**
4. Phase 4 补**弱证据增强层**
5. Phase 5 补**运行时验证层**

你当前的 V2.0 已经有骨架，所以所有 Phase 都应该遵循一个原则：

> **尽量保留 `services.py` 的 orchestrate 形态，新增能力通过新 recaller / classifier / calibrator / verifier 接入，不在 controller 和 job 层堆逻辑。**
