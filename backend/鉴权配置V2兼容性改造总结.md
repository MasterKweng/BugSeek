# 鉴权配置 V2.0 兼容性改造总结

## 改造目标

在保留支持当前所有鉴权类型（Basic Auth, Bearer Token, API Key, Custom, OAuth 2.0, Session, Digest, AWS）的前提下，实现报错.md 中描述的新架构：
- **注入逻辑**（Injection）：定义如何将凭证注入到请求中
- **获取逻辑**（Acquisition）：定义如何获取凭证（静态/动态）

## 兼容性设计原则

### 1. 数据模型兼容
- **保留所有原有字段**：确保 V1 配置继续正常工作
- **新增 V2.0 专用字段**：支持新架构而不破坏现有数据
- **版本标识**：通过 `config_version` 字段区分 V1 和 V2 配置

### 2. 服务层兼容
- **AuthService 双模式支持**：
  - `_perform_login_v1()`：V1 模式登录逻辑（原有逻辑）
  - `_perform_login_v2()`：V2.0 模式登录逻辑（新架构）
  - `_get_auth_headers_v1()`：V1 模式鉴权头生成
  - `_get_auth_headers_v2()`：V2.0 模式鉴权头生成
- **自动路由**：根据 `config_version` 自动选择对应模式

### 3. API 层兼容
- **保留 V1 API 端点**：`/api/v1/projects/{project_id}/auth-config/*`
- **新增 V2.0 API 端点**：`/api/v1/projects/{project_id}/auth-config/v2/*`
- **Pydantic 模型分离**：
  - `AuthConfigCreate/Update`：V1 模式
  - `AuthConfigV2Create/Update`：V2.0 模式

## 数据模型改动

### 新增字段（V2.0）

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `config_version` | VARCHAR(10) | 'v1' | 配置版本标识（v1/v2） |
| `source_mode` | VARCHAR(20) | 'static' | 来源模式（static/dynamic） |
| `static_token` | TEXT | NULL | 静态 Token |
| `injection_config` | JSON | NULL | 注入逻辑配置 |
| `acquisition_config` | JSON | NULL | 动态获取配置 |
| `cache_ttl` | INTEGER | 3600 | Token 缓存有效期（秒） |

### injection_config 结构（JSON）
```json
{
  "key": "Authorization",
  "value_template": "Token {token}",
  "add_to": "header"
}
```

### acquisition_config 结构（JSON）
```json
{
  "url": "https://api.example.com/login",
  "method": "POST",
  "headers": {"Content-Type": "application/json"},
  "data": {"username": "{{username}}", "password": "{{password}}"},
  "extract_rule": {
    "type": "jsonpath",
    "expression": "$.data.token",
    "target_var": "ACCESS_TOKEN"
  }
}
```

## API 接口改动

### V1 API（保留，向后兼容）
```
POST   /api/v1/projects/{project_id}/auth-config

GET    /api/v1/projects/{project_id}/auth-config
DELETE /api/v1/projects/{project_id}/auth-config

```

### V2.0 API（新增）
```
POST /api/v1/projects/{project_id}/auth-config/v2
PUT  /api/v1/projects/{project_id}/auth-config/v2
GET  /api/v1/projects/{project_id}/auth-config/v2
```

## 执行流程

### V1 模式（向后兼容）
1. 读取原有字段（login_url, token_extract_expression 等）
2. 执行登录并提取 Token
3. 根据 auth_type 格式化 Token
4. 注入到请求中

### V2.0 模式（新架构）
1. 检查 `source_mode`
   - `static`：直接使用 `static_token`
   - `dynamic`：从 `acquisition_config` 读取登录配置，执行登录
2. 从 `injection_config` 读取注入规则
3. 使用模板变量替换生成最终值
4. 注入到请求中

## 优势

1. **完全向后兼容**：现有 V1 配置无需修改，继续正常工作
2. **渐进式升级**：用户可以逐步迁移到 V2.0，无需一次性改造
3. **功能增强**：支持更灵活的注入逻辑（如 `Token {token}` 而非固定的 `Bearer {token}`）
4. **解耦设计**：获取逻辑与使用逻辑分离，变更互不影响
5. **符合规范**：
   - 统一响应体 `{ code, message, data }`
   - 全链路 TraceID
   - IDOR 防御
   - 魔法值清理（使用枚举）

## 注意事项

1. **V1 到 V2.0 迁移**：需要前端提供迁移工具或手动配置
2. **测试登录接口**：V1 和 V2.0 都需要测试登录功能
3. **缓存机制**：V2.0 使用统一的 `cached_token` 字段
4. **阻断递归**：V2.0 执行登录接口时需要清空全局鉴权配置（待实现）
